## Pain point

This pattern was developed in both the [extract planning 
app](https://github.com/i-dot-ai/extract-app/) and 
[Minute](https://github.com/i-dot-ai/minute/). In both cases was a need to 
display a long list of "jobs" each with a link to further details page, 
quick actions both on individual jobs and for bulk actions.

## Solution

The arrived at pattern was to develop a "summary" variant of the table component
with checkboxes, full width item link and a action column.

### When to use this pattern

Use a summary table when:

-   users need to scan a list of items and act on individual rows
-   each item has a small, consistent set of actions (for example rename or
    export)
-   users may need to select one or more items to act on them together


### How it works

-   The table uses the `summary` and `subtle` variants for a lighter,
    denser layout suited to internal tools.
-   Each row starts with a small, subtle checkbox for selection. The label is
    visually hidden but still read out to screen readers.
-   The title column uses `stretch` so it takes the remaining width, while the
    date and actions columns use `noWrap` so they stay on one line.
-   Row actions use a `ButtonGroup` of small, tertiary buttons to keep them
    unobtrusive.

### When not to use this pattern

Do not use a summary table for presenting a single record's details — use a
[summary list](/components/summary-list) instead. For simple tabular data with
no actions, use the standard [table](/components/table).
