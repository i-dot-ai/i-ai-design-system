## Context

As mentioned in the [001 - Adapt the GOV.UK Design System](/decisions-record/adapt-govuk-design-system) decision record, the GOV.UK Design System was not specifically designed for web apps and as a result inputs, including buttons, have been designed to draw the attention of the reader and not be msised when scanning a form to be filled in.

The advice on buttons from GOV.UK Design System is to:

> _Before adding lots of secondary buttons, try to simplify the page or break the content down across multiple pages._

However, in the context of web apps which are designed to be used multiple times, splitting content to different pages often leads to a less user-friendly experience.

### Scenarios where the GOV.UK buttons might need to be adapted:

-   **Scenario 1:** When buttons are not the primary action of the page, the attention of the user is drawn to the buttons and they are more likely to be clicked or confused at what they are meant to do.
    
    In the example below, you can see the **Rename** and **Delete** strongly draw the eye whereas the primary action is actually to click on the title and view the item in full.
    
    ![Screenshot an item with link and a rename and delete button.](/images/non-primary-action-buttons.webp)
-   **Scenario 2:** When there are multiple buttons on the page, the buttons are difficult to distinguish from each other and quickly navigate between actions.
    
    Again the primary action of this page is to read the text content below, your attention to the buttons should only be drawn when needed. E.g. User first decides they want to download the summary, they then look for the download button. As opposed to reading all options first and remembering which one they wanted to click.
    
    ![Screenshot a page with multiple buttons.](/images/multiple-secondary-buttons.webp)
-   **Scenario 3:** Where there are tags and buttons on the same page, it can be difficult to distinguish between the two and quickly navigate between actions.
    
    ![Screenshot a page with tags and buttons.](/images/gov-notify-button-and-status-tag-clash.webp)

### Accessibility

To be fully accessible, [interactive elements should be easy to identify](https://www.w3.org/WAI/tips/designing/#ensure-that-interactive-elements-are-easy-to-identify). Both the similarity to the tag component and the squareness of the buttons does not help identify as interactive elements. This was also found in [research done by the NHS](https://service-manual.nhs.uk/design-system/components/buttons#research) where they said that:

> _"We based our buttons on the GOV.UK designs. But because our logo is a blue rectangle and a number of our components (including panel headings) have squared edges, we decided that GOV.UK buttons did not stand out enough. The square buttons did not look clickable next to the other square components._
>
> _We made the buttons more "buttony" by rounding the corners (adding corner radiuses). There is research to suggest that rounded corners make things more clickable._
>
> _Our testing confirmed this. Users were able to complete tasks using buttons and they did not confuse them with non-clickable components."_

Any proposed changes to the buttons should be obviously clickable and distinguishable from other components.

## Decision

The proposal is to make the following changes to the buttons:

-   ### Rounded corners
    
    The proposal is to add a border radius to the buttons. This will imply greater interactivity than the square corners of the GOV.UK buttons.
    
-   ### Primary button colours
    
    The suggestion is that introducing the green in the primary button in the GOV.UK Design System is deliberately outside of the colour palette in order to draw maximum attention to the primary action on the page.
    
    However, in web apps, there are often actions which the secondary button is too "quiet" but the green is too "loud".
    
    Where this scenario has come up in other GOV.UK services you can see they have adopted the Gov UK blue colour as a background:
    
    -   #### GOV.UK Notify
        
        The three main options for API integration have gov around this by using inverted links on a blue background.
        
        ![Screenshot of a gov notify page with three options blue background and inverted links.](/images/govuk-notify-blue-buttons.webp)
    -   #### Civil service jobs
        
        The "email me jobs like these" button has a blue background.
        
        ![Screenshot of a civil service jobs page with a green button and a blue button.](/images/civil-service-jobs-blue-button.webp)
    
    Rather than have a primary, secondary and tertiary button, the proposal is to change the background of the primary button to the GOV.UK blue colour **#1d70b8**. This will still be within the blue pallete of the overall site but still "loud" enough to give the attention of a primary action.
    
-   ### Secondary button colours
    
    The background colour of the secondary button is **##f3f3f3**. This only has a contrast of **1.1:1** which is very light against the white background of the page. This was ok in traditional GOV.UK pages as they were designed to be positioned below a form or text, normally alongside a primary button so that interactivity was clear.
    
    However, in web apps, there is often the need for buttons to be positioned elsewhere on the page, in order to manage users attention. In the case of a toolbar, you may have a list of multiple buttons, none of which are a primary action. We therefore cannot rely on being next to the primary button to give the user a clear indication of interactivity.
    
    The proposal is to change the background of the secondary button to the GOV.UK light blue colour **#d2e2f1**. This is a stronger constrast ratio of **1.32:1** which still requires the box shadow for the contrast, but is more clearly interactive than the current light grey.
